Can a later event decide what a network remembers?

In the brain, a fresh memory is fragile. It leaves a temporary tag, and it becomes permanent only if a salient event supplies plasticity-related products while the tag is still there. This lab shows a simplified version of that mechanism inside a neural network trained with backpropagation, using results from logged training runs. The timeline at the top is computed from the model's equations as an illustration.

2. The start of a new task rescues an older one

Now a salient event is set at the start of a new task B. Its onset rescues task A retroactively, but only while A's tags last. If tags belong to the weight, B's own learning re-tags the same weights and still rescues A long after A's own tags have faded. If tags belong to the change, the window is clean.

3. Why does it remember? The network's own record

Every capture is logged: which event supplied the products, and whose learning was captured. The chart tests that record: resetting the weights the log attributes to one task lowers accuracy on that task and spares the other. Ranking weights simply by how much each task changed them gives the same result for task A, so for task A the log mainly reflects which task changed which weights.

4. Does it prevent forgetting?

On Split-MNIST, a standard benchmark of five digit tasks in a row, consolidation alone does not stop forgetting: consolidated weights are not protected from later learning. Using the consolidation record as the importance signal for protecting weights helps about as much as Elastic Weight Consolidation, though less than Synaptic Intelligence. The difference is that importance comes from capture events after learning rather than being fixed at the time of learning. The surprise detector that triggers these events fires a few times per task and does not reliably mark task changes. When each task has its own output head, every method is close to the ceiling.
